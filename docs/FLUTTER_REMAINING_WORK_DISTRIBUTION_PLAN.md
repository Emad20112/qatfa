# خطة توزيع المهام المتبقية لتطبيق Flutter (منصة قطفة)
## تقسيم العمل إلى ثلاثة أجزاء متوازنة (3-Agent Work Distribution Plan)

---

## 1. المقدمة وحالة المشروع الراهنة
تم بحمد الله وتوفيقه إنجاز المرحلة الأولى التأسيسية لتطبيق الهاتف المحمول (Flutter) لمنصة **قطفة (Qatfa)** بنجاح كامل:
- تم فحص وتحليل الصور الخمس المرجعية في `apps/mobile/images_ui` ومعالجة الفجوات الناتجة عن الذكاء الاصطناعي ومطابقتها مع وثائق المتطلبات (الوثائق 21 و 22 و 13 ووثيقة الأداء 01).
- تم تشييد **البنية التحتية لنظام التصميم (Design System)** في مجلد `apps/mobile/lib/core/` (الألوان الفاتحة والداكنة، الخطوط العربية بنظام القاهرة، المسافات، الظلال، حماية تكبير الخطوط `TextScalerBoundary`، والأزرار والرقاقات والشارات والبطاقات وشريط التنقل السفلي والترويسة التراثية).
- كافة اختبارات الويدجت تعمل بنجاح بنسبة 100%، والتحليل الساكن خلو تام من الأخطاء والتحذيرات (`No issues found`).
- تم توثيق وحفظ مهارات التطوير في مجلد `.agents/` داخل المستودع.

## 2. جدول توزيع المهام بين الوكلاء الثلاثة (Work Distribution Matrix)

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                        توزيع المهام بين الوكلاء الثلاثة                                │
├────────────────────────────┬─────────────────────────────┬─────────────────────────────┤
│      الوكيل الأول (Agent 1) │       الوكيل الثاني (Agent 2)│       الوكيل الثالث (Agent 3)│
│       [هذا الوكيل الحالي]   │        [فرع العمل: main]    │[فرع منفصل: feature/seller..]│
├────────────────────────────┼─────────────────────────────┼─────────────────────────────┤
│ • طبقة البيانات والشبكة    │ • موجز القطفات اليومية      │ • تدفق المقاوتي والنشر السريع│
│   (DioClient + Tokens)     │   (HomeScreen / FeedView)   │   (QuickPublish < 30s)      │
│ • النماذج والمستودعات      │ • البحث الذكي بالميزانية    │ • شاشة الحجوزات والمتابعات   │
│   (Models & Repositories)  │   (BudgetSearch ±10%)       │   (BookingsScreen)          │
│ • الـ BLoCs المركزية       │ • خريطة ودليل الأسواق       │ • شاشة الحساب والملف الشخصي │
│   (FeedBloc, MarketsBloc)  │   (MarketMap & Stalls)      │   (ProfileScreen)           │
│ • هيكل التطبيق والـ Shell  │ • تفاصيل القطفة الكاملة     │ • التحكم المزدوج للمتجر     │
│   (AppRouter & MainShell)  │   (DropDetailScreen)        │   (Master Store Toggle)     │
└────────────────────────────┴─────────────────────────────┴─────────────────────────────┘
```

## 3. تفاصيل مهام الوكلاء

### 3.1 مهام الوكيل الأول (Agent 1 - هذا الوكيل):
**المسؤولية:** النواة الهندسية، طبقة البيانات والشبكة، المستودعات، وإدارة الحالة المركزية (Data & BLoC Infrastructure).
1. **طبقة الشبكة والاتصال بالسيرفر (`lib/data/services/`):**
   - بناء `DioClient` مع اعتراض الطلبات (Interceptors) لإلغاء الاتصالات المتداخلة عبر `CancelToken`.
   - إعداد معالجة الأخطاء والشبكة الضعيفة ووضع عدم الاتصال (Offline Resilience).
2. **النماذج والمستودعات (`lib/data/models/` & `lib/data/repositories/`):**
   - نماذج: `DropModel`, `MarketModel`, `StallModel`, `SellerProfileModel`.
   - واجهات وتنفيذ المستودعات: `IDropsRepository`, `IMarketsRepository`, `ISellerRepository`.
3. **مكونات منطق الأعمال والـ BLoC المركزية (`lib/logic/blocs/`):**
   - `DropsFeedBloc` (إدارة عروض اليوم، التمرير اللانهائي، وسحب للتحديث مع `droppable`).
   - `MarketsBloc` (جلب الأسواق والمحافظات ودبابيس المفارش).
   - `CitySelectorBloc` (حفظ واختيار المحافظة الحالية في التخزين المحلي).
4. **هيكل التطبيق والتوجيه (`lib/app/`):**
   - إعداد `AppRouter` و `MainShellScreen` لربط شريط التنقل السفلي المطور.
   - حقن التبعيات (Dependency Injection عبر GetIt / RepositoryProvider).

---

### 3.2 مهام الوكيل الثاني (Agent 2 - على فرع `main`):
**المسؤولية:** شاشات استكشاف وتجربة المشتري، البحث الذكي بالميزانية، وخريطة الأسواق (Buyer Discovery & Experience).
* **فرع العمل:** `main` (يواصل العمل مباشرة بعد رفع الوكيل الأول للكود).
* **الشاشات والمكونات المكلف ببنائها:**
  1. **شاشة الرئيسية وموجز قطفات اليوم المتجددة (`HomeScreen`):**
     - ربط الترويسة `QatfaAppBarHeader` مع محدد المحافظة.
     - شريط رقاقات أنواع القات مع الفلترة اللحظية من الذاكرة المحلية (همداني، أرحبي، شامي...).
     - بانر العرض المميز (Hero Featured Drop Card) مع زر نداء الإجراء العقيقي.
     - شبكة عروض القطفات باستخدام بطاقة `DropGridCard` مع دعم التمرير اللانهائي والتحميل الهيكلي `QatfaShimmerBox`.
  2. **نافذة البحث الذكي بالميزانية والفلترة المتقدمة (`SmartBudgetSearchModal`):**
     - حقل إدخال المبلغ المتوفر في جيب المشتري (مثلاً 8,000 ريال).
     - محرك البحث بنطاق مرن ($\pm 10\%$) مع تطبيع النصوص العربية (`Arabic Normalization`).
     - فلترة حسب السوق ونوع القات والجودة (رووس، عوارض، قطل...).
  3. **دليل الأسواق والخريطة التفاعلية (`MarketsScreen` & `MarketMapScreen`):**
     - قائمة الأسواق الشعبية باستخدام بطاقة `MarketSummaryCard`.
     - عرض الخريطة التفاعلية الخفيفة مع دبابيس المفارش (دبوس أخضر للمتوفر، ودبوس رمادي للمنتهي) وبطاقة المعاينة المنبثقة.
  4. **شاشة تفاصيل القطفة الكاملة (`DropDetailScreen`):**
     - معرض الصور المتعدد (Image Carousel) مع شارة `[📷 صورة حقيقية من السوق اليوم]`.
     - بطاقة بيانات المقاوتي المعتمد والتقييم.
     - مصفوفة مواصفات القطفة الأربعة (درجة النعومة، نسبة العيدان 90%، وقت القطف 4:30 فجراً، طريقة الحفظ).
     - شريط السعر البارز وزرا الإجراء السريع (اتصال هاتفي ومحادثة وحجز مباشر عبر WhatsApp).

### 3.3 مهام الوكيل الثالث (Agent 3 - على فرع منفصل `feature/seller-flow-and-profile`):
**المسؤولية:** تدفقات المقاوتي والنشر السريع، الحجوزات والمتابعات، والملف الشخصي (Seller Publisher, Bookings & Profile).
* **فرع العمل:** `feature/seller-flow-and-profile` (يُنشأ ويتفرع من `main`).
* **الشاشات والمكونات المكلف ببنائها:**
  1. **واجهة النشر السريع للمقاوتي بالكاميرا الحية (`QuickPublishFlow`):**
     - نشر العرض خلال **أقل من 30 ثانية** وبأقل من 3 نقرات ملائمة لشمس السوق وانشغال اليدين.
     - شاشة إعداد القوائم المسبقة (Presets) لأنواع القات وأصنافه المعتادة لتفادي الكتابة اليدوية.
     - التحكم المزدوج: مفتاح المتجر العام ومفتاح المنتج الفردي [متوفر / نفد].
  2. **شاشة الحجوزات والمتابعات (`BookingsScreen`):**
     - تبويبات حالات الحجز (الكل، قيد التأكيد، مؤكد، مكتمل) مع العدادات.
     - قائمة بطاقات الحجوزات `BookingCard` وأزرار الإجراء السريعة (إلغاء حجز / اتصال بالمقاوتي / تقييم التجربة).
     - بطاقة الملخص المالي والكمي الإجمالي أسفل الشاشة.
  3. **شاشة الحساب والملف الشخصي (`ProfileScreen`):**
     - رأس الحساب مع صورة المستخدم وشارة التوثيق ومبدل الصفة `[ مشتري ▼ / مقاوتي ]`.
     - شريط الإحصائيات الثلاثي `StatCounterCard`.
     - قائمة خيارات الحساب والأسواق المفضلة والإشعارات والدعم الفني وتسجيل الخروج.
     - التذييل التراثي بمدرجات جبال اليمن وشعار *"مع قطفة .. نزرع الخير ونحصده معاً"*.
* **قاعدة الانتهاء:** يرفع الوكيل الثالث فرعه إلى المستودع (`git push -u origin feature/seller-flow-and-profile`) **دون دمجه في main**.

## 4. إرشادات وقواعد عمل إلزامية لكافة الوكلاء (Mandatory Agent Guidelines)

1. **الالتزام بالوثائق المرجعية:**
   - قراءة واعتماد المتطلبات والسياسات في:
     - `docs/04-functional-requirements.md`
     - `docs/08-mvp-scope.md`
     - `docs/21-client-proposal.md`
     - `docs/22-user-flows-detailed.md`
     - `docs/23-screen-specifications-detailed.md`
     - `docs/architecture/performance/01_FLUTTER_PERFORMANCE_STRATEGY.md`
2. **الالتزام بالـ Commits المستمرة:**
   - عمل `git commit` فوري ومستقل بمجرد الانتهاء من كل شاشة أو مكون مع رسالة دقيقة بصيغة Conventional Commits (مثل `feat(mobile): ...`).
3. **استخدام مهارات `.agents`:**
   - الاستعانة بالمهارات الموجودة في مجلد `.agents/skills/`:
     - `flutter-apply-architecture-best-practices`
     - `flutter-build-responsive-layout`
     - `flutter-fix-layout-issues`
     - `flutter-add-widget-test`
4. **حماية التجاوب وتكبير الخطوط:**
   - تطويق الواجهات دائماً بـ `TextScalerBoundary` لتفادي أخطاء الـ Overflow.
   - استخدام رموز التصميم الموجودة حصراً في `lib/core/theme/` وعدم اختراع قيم ألوان أو مقاسات ثابتة.
5. **الفحص قبل الرفع:**
   - تشغيل `flutter analyze` والتأكد من عدم وجود أي خطأ أو تحذير قبل إتمام العمل.
